# virtual-memory-management-simulator
C simulation of virtual memory management using page traces, shared memory, semaphores and multiple processes developed as part of an Operating Systems course assignment.
The project simulates memory references generated by two processes and manages them through a central Memory Manager using shared memory, POSIX semaphores and a hash-based page table.

## Overview
- Two producer processes (`PM1` and `PM2`)
- One Memory Manager
- Shared memory buffers
- POSIX semaphores for synchronization
- Memory trace files
- A hash-based page table

Each producer reads memory references from a trace file and sends them to the Memory Manager.
The Memory Manager processes the references, detects page faults, tracks dirty pages and performs page replacement using the Flush-When-Full (FWF) strategy.

## Features
- Two concurrent producer processes
- Memory trace processing
- Page number extraction from virtual addresses
- Shared memory communication
- Semaphore-based synchronization
- Hash-based page table
- Page fault detection
- Dirty page tracking
- Disk read/write statistics
- Flush-When-Full page replacement
- Separate frame allocation for the two processes
- Configurable number of frames
- Configurable page-fault threshold
- Configurable request block size
- Optional limit on the number of trace references processed

## Producer Processes
The system creates two producer processes:
- PM1 reads from bzip.trace
- PM2 reads from gcc.trace

Each producer:
1. Reads memory references from its trace file.
2. Determines whether the operation is a read or write.
3. Sends the request to the Memory Manager through shared memory.
4. Signals the Memory Manager using POSIX semaphores.

## Memory Manager
The Memory Manager:
- Receives requests from both producers
- Converts virtual addresses to page numbers
- Searches for pages in the page table
- Detects page faults
- Tracks dirty pages
- Performs Flush-When-Full replacement
- Maintains statistics for each process

The page number is extracted from the virtual address using "address >> 12" which corresponds to a 4 KB page size.

## Page Replacement
The project uses a Flush-When-Full (FWF) strategy.
When the page-fault threshold is exceeded or the allocated frames for a process are full, all pages belonging to that process are removed from memory.
Dirty pages are counted as disk writes when they are flushed.

## Inter-Process Communication
Communication between the producer processes and the Memory Manager is implemented using:
- POSIX shared memory
- Named POSIX semaphores
- Circular buffers

Each producer has its own shared memory region and synchronization semaphores.

## Statistics
At the end of execution, the program prints statistics for each process and overall totals.
- Number of memory references
- Page faults
- Disk reads
- Disk writes
- Frames still in use

## Source Files

### main.c
Initializes the Memory Manager, creates the two producer processes and starts the simulation.

### PM1.c
Reads memory references from the bzip.trace file and sends requests to the Memory Manager.

### PM2.c
Reads memory references from the gcc.trace file and sends requests to the Memory Manager.

### MM.c
Implements the Memory Manager.
- Page table operations
- Page faults
- Frame allocation
- Dirty pages
- Flush-When-Full replacement
- Statistics

### IPC.c
Implements the shared memory and semaphore communication between the producers and the Memory Manager.

### IPC.h
Contains:
- Shared memory identifiers
- Semaphore identifiers
- Trace file paths
- Buffer structures
- Request structures
- IPC function declarations

### MM.h
Contain the structures used by the Memory Manager, including:
- Page frames
- Statistics
- Memory Manager state

## Compile
```bash
make
```

## Usage
```bash
./main k totalFrames q [max]
```
- k: Page-fault threshold used by the FWF
- totalFrames: Total number of available page frames.
- q: Number of references processed from one producer before switching to the other.
- max: Optional maximum number of references read from each trace file.

## Example
```bash 
./main 5 20 10 OR ./main 5 20 10 1000
```
